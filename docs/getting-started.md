# Getting started (consumer)

How to adopt the framework in your project and keep it current. This is the consumer's view; to
develop the framework itself, see [`../AGENTS.md`](../AGENTS.md).

## 1. Initialise

```bash
npx @zizzfizzix/aef init --interactive
```

The wizard asks for your harness(es), ORM, UI/design system, and stack, writes
`framework.config.json`, then:

- renders the selected skills into `.ai/skills/<skill>/SKILL.md` (one flat file each),
- snapshots a BASE under `.ai/.base/` and a `.ai/.render-manifest.json` (sync's merge base),
- installs the conventions: `AGENTS.md` (from the template, with your project name), `CLAUDE.md`,
  and the `.ai/specs`, `.ai/qa`, `.ai/runs`, `.ai/lessons.md` scaffolding,
- creates the `.ai/framework-feedback/` outbox and the read-only `.ai/lessons.framework.md`,
- wires each harness's skills directory (e.g. `.claude/skills/<skill>` → the rendered skill).

Non-interactive:

```bash
npx @zizzfizzix/aef init --config framework.config.json   # see README for the schema
npx @zizzfizzix/aef init --copy                            # copy into harness dirs instead of symlinking
```

Commit the result. The rendered `SKILL.md` files carry a `generated by aef render` header —
you _may_ edit them; `sync` preserves your edits via 3-way merge.

## 2. Keep it in sync

```bash
npx @zizzfizzix/aef sync
```

For each installed skill, `sync` re-renders from the (updated) framework source and reconciles:

- **framework unchanged** → left alone (your local edits kept);
- **framework changed, no local edits** → fast-forwarded to the new render;
- **both changed** → git-native 3-way merge. Clean merges apply silently; genuine conflicts land
  as standard `<<<<<<<` / `>>>>>>>` markers in the working tree. Review with `git diff`, resolve,
  commit — the same ritual as any merge. A non-zero exit (2) signals unresolved conflicts.

`sync` also refreshes the read-only `lessons.framework.md`.

## 3. Change your stack selection

```bash
npx @zizzfizzix/aef add mikro-orm       # select an adapter (axis inferred from its adapter.json)
npx @zizzfizzix/aef remove drizzle      # deselect; uninstalls skills that needed that axis
```

`add`/`remove` re-render affected skills, install/uninstall as needed, and 3-way-merge survivors
so your local edits are preserved. Removing the last adapter on an axis uninstalls that axis's
skills.

## 4. Contribute fixes back (optional)

If a rendered skill is wrong or a workflow should change for everyone, install the opt-in
`improve-framework` skill and run it: it routes your fix to the right framework source fragment
(via provenance), validates with the framework's gate, opens a framework PR, and syncs the result
back. Generic lessons you capture (scope `framework` / `adapter:*`) collect in
`.ai/framework-feedback/` and upstream the same way; project-specific ones stay in `.ai/lessons.md`.
