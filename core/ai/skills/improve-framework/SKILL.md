# Improve the framework (from a consumer repo)

You are in a **consumer** repo. Rendered skills under `.ai/skills/<skill>/SKILL.md` are generated
(`<!-- generated by aef render … -->`). Editing them locally is fine, but the fix only sticks
for everyone if it lands in the **framework source**. This skill routes a change there, validates
it, opens a PR, and brings it back down.

Two modes:

- **Direct fix** — something is wrong/missing in a rendered skill or adapter.
- **Feedback drain** — upstream scope-tagged lessons from `.ai/framework-feedback/`.

## 0. Prerequisites

- Read `framework.config.json`:
  - `source.path` → a local framework checkout to edit. If null, clone `source.repo` into a
    scratch dir and work there.
  - `feedback.upstream` → `channel` (`pr`/`issue`/`fork`), `sanitize`, `requireHumanApproval`.
- Confirm the framework checkout is clean and on an up-to-date default branch; create a feature
  branch before editing.

## 1. Locate the source of the symptom (provenance)

Never guess where content comes from. For the affected skill, open
`.ai/skills/<skill>/provenance.json`. Each `regions[]` entry is
`{ source, adapter, slot, startLine, endLine }` (body-relative lines, line 1 = first line after
the 2-line header). Map the offending text to its region:

- `slot: null` → the text comes from the **generic body** `core/ai/skills/<skill>/SKILL.md`. A fix
  here changes the workflow for **all** consumers regardless of adapter.
- `slot: "<axis>.<key>"`, `adapter: "<name>"` → the text comes from
  `adapters/<axis>/<name>/<fragment>`. A fix here only affects consumers on that adapter.

Decide placement deliberately:
| Symptom | Edit |
|---------|------|
| Wrong/missing stack-specific detail (this ORM/UI lib) | the adapter fragment |
| Wrong/missing general workflow or rule | the generic body |
| A whole capability is missing for one stack | add a new `<axis>.<key>` slot to the generic body, then fill it in every adapter on that axis (use the `adapter-creator` skill) |

## 2. Make the change in the framework source (delegate to a subagent)

Spawn a subagent to work in the framework checkout so this session's context stays clean. Instruct it to:

1. Apply the **minimal** edit at the location from step 1. One logical change.
2. Run the gate: `pnpm gate`. It must pass — deterministic output, no leftover
   `SLOT:` markers, every declared slot fillable. **Never** proceed on a failing gate; fix the
   determinism/slot problem first.
3. If a rendered shape is worth eyeballing, render the affected skill
   (`pnpm cli render --skill <skill>`) and inspect.
4. Report back the `git diff` and the gate result.

## 3. Open a framework PR (human-gated at merge)

- Commit on the feature branch with a clear message; push; open a PR (or `issue`/`fork` per
  `feedback.channel`).
- **Do not merge.** `requireHumanApproval` means a human reviews and merges upstream.
- Keep the PR description to the generalized change + rationale.

## 4. Bring the fix back

Once the change exists in the framework source (merged, or locally for a fast loop):

- Run `aef sync --out <thisRepo>`. It re-renders and 3-way-merges, preserving any unrelated
  local edits and surfacing conflicts as standard `<<<<<<<` markers.
- Review with `git diff`, resolve any conflict, commit. The local edit that started this is now
  the rendered output of the upstreamed source — no manual port-back.

## Feedback drain mode

When asked to upstream lessons (or on a scheduled run):

1. Read `.ai/framework-feedback/*.md`. Each entry carries a `scope`:
   - `project` → **never upstream**; it belongs in local `.ai/lessons.md`.
   - `framework` / `adapter:<axis>:<name>` → candidate for upstream.
2. **Sanitize** (required when `sanitize: true`): keep only the generalized rule + a scrubbed
   minimal repro. Strip secrets, proprietary identifiers, customer names, internal URLs, and raw
   source dumps. If you cannot sanitize an entry, skip it and flag it for a human.
3. Classify each entry's target (generic body / adapter fragment / framework `lessons.md`) using
   the same provenance logic as step 1, and **batch** them.
4. Run steps 2–3 of Direct fix (subagent edit + gate) for the batch, then open **one** PR.
5. Mark upstreamed entries (e.g. move to `.ai/framework-feedback/.upstreamed/`) so they are not
   re-sent. They retire from the consumer once they arrive back via `sync` in `lessons.framework.md`.

## Guardrails

- Human-gated at **merge**, never auto-merge.
- Sanitize before anything leaves the repo; for a private consumer route to the private `fork`.
- The `check-render` gate is mandatory — a PR that fails it is not opened.
- Prefer editing the generic body only when the change is truly stack-agnostic; otherwise an
  adapter. When unsure, ask.
